业财一体化经营数据体系建设

IT 半年度工作规划

建立运营、财务、资金三方共用一套可信数据的经营管理体系。先完成按天的运营管理报表与财务管理报表，并实现相互核对；再建设财务月表与资金对账体系；过程中持续完善口径、规则和业务系统，为后续企业管理系统和自动化打基础。

0一页摘要

要达成什么

  • 按天的运营管理报表，服务目标达成、团队绩效、补货、定价等经营决策
  • 与之对应的财务管理报表，两边可逐项核对
  • 财务月表与资金对账体系，经营、财务、资金三方可核对

为什么现在做不到

  • 运营报表由两人分别制作，口径不统一
  • 财务除档口外以手工表格充当凭证，按结算口径确认收入，缺发货口径和准确成本
  • 一物多码等基础数据不统一，各平台口径各异

核心思路：一份数据，多种口径

同一套订单明细同时记录创建、支付、发货、结算四个时间。按支付时间汇总得到运营日报，按发货时间汇总得到财务管报，按结算账单得到财务月报。运营与财务数据同源，差异只来自时间归属，可以逐单追溯。

怎么推进

  • 第一阶段：运营天表、财务天表，实现平台 ↔ 运营 ↔ 财务核对；在天表基础上建立目标达成、团队绩效、补货、定价等经营分析模型
  • 第二阶段：财务月表、资金对账，先跑起来再逐步做准
  • 第三阶段：企业管理系统串通主流程，自动化、智能化

1目标

名称：业财一体化经营数据体系建设

总目标

建立运营、财务、资金三方共用一套可信数据的经营管理体系，用数据支撑经营决策：

  • 管理报表直接服务经营：跟踪目标达成、评估团队绩效、给出补货建议、支撑定价策略、评估广告投放效果、分析商品款式表现（爆款、滞销、新品）、预警库存周转与滞销、对比渠道和店铺盈利以分配资源。
  • 三方数据逐级可核对：经营口径与财务口径核对，财务口径与资金口径核对，差异能说明来源。

分目标（按优先级）

分目标说明
1. 按天的运营管理报表按国家、平台、店铺、商品按天产出，让运营和管理层每天看到目标达成、团队绩效、库存与补货、价格与利润空间，及时调整经营动作。
2. 对应的财务管理报表与运营报表口径对应。天表只含直接成本和费用，看各渠道、店铺、商品的贡献利润；月表在天表基础上加入报销、薪资等其他成本和费用，得出完整经营利润。
3. 统一规则、口径，完善系统收入确认、成本、费用归类、主数据、手工凭证与将来自动凭证的对账规则；按业财一体化需要补齐业务系统功能。
4. 准确的现金流量表准确反映各主体、各账户的资金收支和余额，并与财务口径数据核对。
延伸目标（逐步实现，不限于本半年度）：自动生成凭证、业务系统与电商平台全面打通、AI 辅助经营分析。

2现状

渠道与国家国内：1688 分销、档口、未来国内电商；俄罗斯：自营仓 + Ozon / WB 的 FBS、FBO；美国：亚马逊、TikTok；墨西哥：美客多；韩国：Coupang。
主体与币种国内各主体公司 + 跨境主体公司；人民币、卢布、美元、墨西哥比索、韩元。
供应链与物流货品经领猫打版、大货生产后在聚水潭采购入库到国内自营仓，再按地区调拨：俄罗斯线发往俄罗斯自营仓后，FBO 送入平台官方仓、FBS 由自营仓发货；亚马逊线发往平台官方仓，由平台配送到消费者。
财务档口用金蝶；其余业务以手工表格充当凭证；收入按结算账单口径确认。
数据与报表运营报表由两人分别制作；数据存放在本地数据库，不利于企业重要数据留存。

渠道、主体、币种、履约模式组合多，货物经过多段仓储和运输，各平台数据格式、结算周期、费用名目都不同，口径统一和管理难度大。

3问题

业务扩张快于财务核算和数据体系建设，报表出不来、不及时、对不上、无法验证。先列报表层面的结果，再列背后原因。

（一）报表层面

R1运营报表由瀚章、立新两人分别制作，口径和数据不统一，缺少跨平台统一的版本。
R2财务管理报表不及时，难以辅助决策。
R3运营与财务数据对不上，差异说不清来源。
R4没有准确的现金流量表。
R5报表准确性和计算逻辑无法验证。

（二）背后原因

A. 基础数据不统一

A1 聚水潭一物多码，用编码区分渠道，销售、成本、库存难以对应
A2 各平台编码自成体系
A3 店铺、主体、国家、币种、团队等主数据口径未统一

B. 收入口径不统一

B1 按结算账单确认收入，结算周期不同，收入滞后、月度错位
B2 缺少按发货时间确认的收入数据
B3 改按发货口径后，与结算账单的对账难度增加
B4 订单从下单到回款各环节未串成一条线
B5 各平台费用名目不统一

C. 成本和库存算不准

C1 跨境落地成本缺数据，头程、关税等未分摊到货品，俄罗斯链路运费分两段
C2 库存分布多处，多段调拨在途缺少统一跟踪和核对

D. 财务核算基础薄弱

D1 除档口外以手工表格作凭证，难追溯、难复核
D2 多主体内部交易未系统化处理
D3 将来自动凭证与当前手工凭证之间缺少对账规则

E. 资金数据分散

E1 资金分布在多主体、多账户、多币种以及各平台未结算余额中，实际资金全貌难汇总

4解决方案

先打基础，再统一口径与规则，最后产出报表并建立核对体系。

方案一：统一基础数据

解决 A1、A2、A3、B5
  1. 商品主数据：清洗聚水潭编码，得到唯一主 SKU；主 SKU 关联领猫，得到唯一主 SKC 和 SPU。各渠道编码作为别名挂在主 SKU 下，用于清洗历史数据；规范运营新建子编码的规则，后续由系统按规则生成规范编码，同时满足运营区分渠道的需要。未来继续向前关联设计环节基础信息，以及国内发往境外货品的原始需求和补货渠道。
  2. 主数据统一口径：主体名称、销售地区、销售渠道、店铺、店铺负责人及子负责人、商品名称、仓库名称、品牌、商品类别（正品、赠品）、商品类目（多级分类，如男女装 → 休闲裤、卫衣）。
  3. 费用科目映射：各平台费用类型逐个映射到统一管理费用科目，财务确认后固定；出现新费用类型时自动提示财务补映射。

方案二：数据自动采集入仓

全部报表的数据来源
  1. 电商平台：Ozon、WB、亚马逊、TikTok、美客多、Coupang，采集订单与发货明细、结算账单与资金流水、广告、平台仓库存、流量转化。
  2. 内部系统：聚水潭（商品、采购入库、库存、调拨、销售出库）、领猫（款式、大货订单）、钉钉（报销审批）、金蝶（档口凭证）。
  3. RPA / 爬虫任务：平台或系统未提供 API 的数据，用 RPA / 爬虫定时任务自动获取。
  4. 钉钉在线表格：标准成本、运营目标、店铺负责人与子负责人关系、主体与渠道对应关系、物流账单、薪资等人工维护数据，在钉钉在线表格中共享维护，系统定时同步。

方案四：成本规则

解决 C1

设两套成本方案，分别服务运营管理和高管决策。

标准成本实际成本
来源商品部门维护的国内成本单价和跨境成本单价（内外主体间售价）领猫下单环节与工厂确认的采购单价，与标准资料包价格比对校验
计算直接取维护价格，不随供应商供价大幅波动按每笔采购入库时间移动加权平均，采购退货逆向计算；按国内仓发货海外出库时间口径把头程分摊到 SKU，得出国内主体销往境外的成本单价
头程—按报价单与发货总重预估，再按单商品重量分摊；头程供应商真实账单到达后核对核销
其他计入—平台发货操作费、快递费，与财务确认后计入实际成本
可见范围运营人员可查看仅老板、高管可查看
用途衡量运营 KPI / OKR 达成，用于团队管理反映真实准确的经营情况，供高管决策

终端销售取同日期海外出库节点的成本单价，节点以发货、清关还是海外仓收货时间为准，与财务确定。

实际成本规则为初步设想方向，具体由财务决策确认后执行。

方案五：退款规则

解决 R3、B3
  1. 取数：按退款创建时间增量拉取全部退款原始记录。
  2. 财务当期口径：按退款成功时间归属统计日期，在当期扣减，对应财务发货口径。
  3. 运营回溯口径：按退款明细携带的单号关联原销售单，取原单支付时间归属，对应运营支付口径。
  4. 部分退款分摊：一个订单多个 SKU、仅退款不退货且未退全额时，按各 SKU 售价占比分摊。
  5. 团队 KPI 考核：采用财务天表的当期退款口径，退款在退款成功当期扣减，已考核期间的数据不因后续退款回溯改动。

方案六：费用、流量、税与币种

解决 B5
  1. 天表费用范围：只放与主营业务关联、可归因的费用。
  2. 商品广告：按广告投放平台的归因规则归属到具体商品。
  3. 店铺、品牌等全局广告：按当天各 SKU 销售额贡献度分摊。
  4. 其余费用（罚款、平台佣金等）：按平台费用科目，按 SKU 销售额贡献度分摊。
  5. 流量数据：直接使用平台已归因的流量数据，挂上公共维度。
  6. 税：按财务标准计算。
  7. 币种：人民币、卢布、美元、墨西哥比索、韩元的折算规则（取交易日、结算日还是月末汇率等），由财务决策后作为执行标准。

方案九：经营分析模型

让报表直接服务经营决策 · 支撑总目标

在销售额天表、成本表、退款表、费用表、流量表、库存表和钉钉在线表格维护的目标表、负责人关系表之上建立分析模型。运营视角一律使用标准成本；同一模型提供给老板、高管的版本使用实际成本。模型中的天数、比例等阈值由运营确定，可随时调整。

1. 目标达成
用到：运营目标表（店铺、团队、月度销售额与利润目标）+ 运营天表（支付口径）
  • 当月达成率 = 当月累计实际 ÷ 当月目标
  • 时间进度 = 已过天数 ÷ 当月天数
  • 进度差 = 达成率 − 时间进度，为负即落后
  • 全月预计 = 累计实际 ÷ 已过天数 × 当月天数
输出：按店铺、负责人、团队每天显示达成率和落后预警，飞书每日推送。
2. 团队绩效
用到：店铺负责人与子负责人关系表 + 运营天表 + 成本表（标准成本）+ 费用表 + 目标表
  • 按负责人、团队汇总销售额、贡献利润、目标达成率
  • 贡献利润 = 销售额 − 退款 − 标准成本 − 平台费用 − 广告费
  • 考核口径：退款采用财务天表的当期退款口径，在退款成功当期扣减
  • 辅助指标：广告投入产出比、退款率、库存周转天数
输出：月度团队与个人绩效排行，作为 KPI / OKR 考核依据。
3. 补货建议
用到：库存表（跨境在仓可发、跨境采购在途、国内仓可调拨）+ 运营天表（销量）
  • 日均销量 = 近 7 天与近 30 天日均加权
  • 可售天数 = （在仓可发 + 在途）÷ 日均销量
  • 可售天数 < 补货周期 + 安全天数 时触发提醒
  • 建议补货量 = 目标天数 × 日均销量 − 在仓可发 − 在途
  • 补货周期按线路设置：国内 → 俄罗斯自营仓、俄罗斯自营仓 → 平台仓、国内 → 亚马逊仓
输出：按 SKU、仓库的补货清单，区分「需补货 / 正常 / 库存过量」。
4. 定价策略
用到：运营天表（售价、销量）+ 成本表 + 费用表（佣金、罚款、广告分摊）
  • 单件贡献利润 = 售价 − 单件成本 − 单件平台费用 − 单件广告费
  • 利润率 = 单件贡献利润 ÷ 售价
  • 保本价 = 单件贡献利润为 0 时的售价
  • 记录每次调价前后的销量与利润变化，评估调价效果
输出：每个 SKU 的利润率、保本价、低于保本价预警，调价前后对比。
5. 广告投放效果
用到：费用表（商品广告按平台归因、店铺品牌广告按销售额分摊）+ 运营天表 + 流量表
  • 投入产出比 = 广告带来的销售额 ÷ 广告费
  • 广告费占比 = 广告费 ÷ 销售额
  • 广告后贡献利润：扣除广告费后的贡献利润是否为正
  • 结合曝光、点击、转化率定位问题环节
输出：按商品、店铺的广告效果排行，标出「高花费低产出」和「扣广告后亏损」的商品。
6. 商品款式表现
用到：商品主数据（SPU、SKC、品牌、类目）+ 运营天表 + 流量表 + 库存表
  • 新品：首单日期在近 N 天内，跟踪上新后的销量、转化爬坡
  • 爆款：近 30 天销量排名前列且环比增长
  • 滞销：近 30 天销量低且可售天数超过阈值
  • 按 SPU、SKC 两级汇总，看款式整体和颜色表现
输出：爆款、新品、滞销三张清单，支撑追单、加推和清货决策。
7. 库存周转与滞销预警
用到：库存表（进销存、在仓、在途）+ 运营天表 + 成本表
  • 周转天数 = 平均库存 ÷ 日均销量
  • 库龄：按采购入库日期分段（如 30 / 60 / 90 天以上）
  • 周转天数或库龄超过阈值即预警
  • 预警库存按成本计算货值，量化积压资金
输出：滞销预警清单与积压货值，运营视角按标准成本，高管视角按实际成本。
8. 渠道和店铺盈利对比
用到：财务天表（贡献利润）+ 财务月表（完整经营利润）+ 主数据（主体、地区、渠道、店铺）
  • 按地区、渠道、店铺对比销售额、贡献利润、利润率
  • 月度加入报销、薪资等费用后对比完整经营利润
  • 计算各渠道利润贡献占比与广告、库存资源占用占比
输出：渠道、店铺盈利排行与资源占用对比，支撑人力、资金、广告预算向高回报渠道倾斜。

方案十：财务天表与月表

解决 R2、D1 · 支撑目标 2
  • 财务天表：按发货口径归属到天，只含直接成本和费用，看贡献利润；与运营天表按同源明细核对。
  • 财务月表：天表科目汇总（收入、成本、一部分营销费用）+ 营业外收入、管理费用、财务费用、研发费用（报销、工资等）。后者波动不大、不影响运营决策，只在月表体现。
  • 协助财务：提供平台数据完善科目对应关系；协助改善报销 OA，帮助报销准确归属到科目。

方案十一：资金对账与对账体系

解决 R4、R5、D2、D3、E1 · 支撑目标 3、4
  • 资金对账月表：按账单口径与资金流水做匹配明细，在此基础上汇总各主体、各账户的资金收支和余额，形成现金流量表。
  • 其他对账表（逐步增加）：期末库存对照库存进销存并下钻单据明细；头程预估与真实账单核对；按需增加。
  • 凭证与自动化：财务规则先保证逻辑正确；凭证模型跑通后，再做自动生成凭证和自动对账。
